# \# Requisitos funcionales – Queen Blossom

# 

# \## Descripción

# 

# Los requisitos funcionales establecen las acciones principales que deberá realizar el sistema Queen Blossom para facilitar la consulta y compra de productos mediante una tienda virtual.

# 

# Estos requisitos fueron identificados durante la etapa de análisis del proyecto y se relacionan con las historias de usuario y los modelos UML desarrollados.

# 

# \## RF-01. Visualizar catálogo de productos

# 

# \*\*Prioridad:\*\* Alta

# 

# El sistema debe mostrar un catálogo de productos con su nombre, imagen, precio y descripción, permitiendo al cliente conocer los artículos disponibles.

# 

# \*\*Criterio de aceptación:\*\* Al consultar el catálogo, se visualiza la información básica de cada producto.

# 

# \## RF-02. Registro e inicio de sesión

# 

# \*\*Prioridad:\*\* Alta

# 

# El sistema debe permitir a los usuarios crear una cuenta e iniciar sesión utilizando sus datos de acceso.

# 

# \*\*Criterio de aceptación:\*\* El usuario puede registrarse e iniciar sesión con datos válidos y el sistema valida los campos obligatorios.

# 

# \## RF-03. Gestionar carrito de compras

# 

# \*\*Prioridad:\*\* Alta

# 

# El sistema debe permitir agregar productos al carrito, eliminarlos y modificar sus cantidades antes de confirmar la compra.

# 

# \*\*Criterio de aceptación:\*\* El total del carrito se actualiza correctamente al agregar, eliminar o modificar productos.

# 

# \## RF-04. Buscar y filtrar productos

# 

# \*\*Prioridad:\*\* Media

# 

# El sistema debe permitir buscar y filtrar los artículos disponibles para facilitar su localización.

# 

# \*\*Criterio de aceptación:\*\* Al realizar una búsqueda o aplicar un filtro, se muestran los productos correspondientes.

# 

# \## RF-05. Revisar resumen del pedido

# 

# \*\*Prioridad:\*\* Alta

# 

# El sistema debe mostrar un resumen del pedido antes de confirmar la compra.

# 

# \*\*Criterio de aceptación:\*\* El cliente puede visualizar los productos seleccionados, las cantidades y el total correspondiente.

# 

# \## Estado de los requisitos

# 

# Los cinco requisitos están documentados y relacionados con las historias de usuario y los modelos UML del sistema.

# 

# Su implementación y validación funcional deberán confirmarse durante las siguientes etapas de desarrollo.
