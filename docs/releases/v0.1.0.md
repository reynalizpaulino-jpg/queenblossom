## 1. Descripción de la versión

La versión 0.1.0 de Queen Blossom representa el cierre de la etapa inicial de análisis, planificación y documentación del sistema.

Queen Blossom es una tienda virtual diseñada para facilitar la consulta de productos, el acceso de usuarios y la organización de compras mediante un carrito digital.

Durante las diferentes actividades de la asignatura se han trabajado los requisitos del sistema, las historias de usuario, los modelos UML y la planificación de las tareas mediante GitHub Projects.

En esta versión se organiza esa información dentro del repositorio, estableciendo una base técnica para continuar con la implementación del sistema.

Esta versión no representa una aplicación completamente funcional, sino una etapa documental del proyecto.

## 2. Contenido de la versión actual

La documentación de la versión incluye los siguientes elementos:

### 2.1. Requisitos del sistema

Se definieron cinco requisitos funcionales:

- RF-01. Visualizar catálogo de productos.
- RF-02. Registro e inicio de sesión.
- RF-03. Gestionar carrito de compras.
- RF-04. Buscar y filtrar productos.
- RF-05. Revisar resumen del pedido.

También se documentaron cinco requisitos no funcionales relacionados con la facilidad de uso, el rendimiento, la seguridad, la adaptabilidad y la compatibilidad con navegadores.

**Ubicación:** `docs/requirements/`

### 2.2. Historias de usuario

Se documentaron cinco historias de usuario que describen las necesidades principales de los clientes.

Estas historias permiten relacionar las funcionalidades del sistema con los criterios de aceptación que deberán comprobarse durante su implementación.

**Ubicación:** `docs/requirements/user-stories.md`

### 2.3. Modelos UML

Se trabajaron cinco diagramas UML para representar la estructura y el funcionamiento previsto del sistema:

- Diagrama de casos de uso.
- Diagrama de clases.
- Diagrama de secuencia.
- Diagrama de actividades.
- Diagrama de colaboración.

**Ubicación:** `docs/design/uml/`

### 2.4. Arquitectura propuesta

Se definió una arquitectura cliente-servidor, organizada en frontend, backend y base de datos.

El frontend seguirá una arquitectura basada en componentes, utilizando React como tecnología propuesta.

El backend estará organizado mediante el patrón MVC (Modelo-Vista-Controlador), complementado con servicios para gestionar las reglas del negocio. Se propone Node.js con Express para su implementación.

La comunicación entre ambas partes se realizará mediante una API HTTP que intercambiará información en formato JSON.

**Ubicación:** `docs/architecture/`

### 2.5. Gestión y seguimiento

Se adoptó la metodología Kanban para organizar las actividades mediante GitHub Projects.

También se documentaron los Issues relacionados con las historias de usuario, las prioridades, los riesgos y las tareas que necesitan seguimiento.

**Ubicación:** `docs/project-management/`

## 4. Aspectos pendientes

Aunque la planificación y la documentación constituyen una base importante, todavía quedan actividades técnicas necesarias para avanzar hacia un sistema funcional.

### 4.1. Desarrollo del frontend

Implementar las pantallas y componentes de la tienda virtual, incluyendo el catálogo, el registro de usuarios y el carrito de compras.

### 4.2. Desarrollo del backend

Implementar los controladores, modelos, servicios y rutas necesarias para atender las solicitudes del frontend.

### 4.3. Base de datos

Seleccionar la tecnología de almacenamiento, diseñar las tablas y relaciones e integrar la base de datos con el backend.

### 4.4. Autenticación y seguridad

Implementar el registro y acceso seguro de los usuarios, las validaciones necesarias y la protección de la información.

### 4.5. Pruebas funcionales

Comprobar que las funciones del catálogo, la búsqueda, el carrito y el resumen del pedido cumplan con los criterios de aceptación.

### 4.6. Revisión de Issues y tablero

Mantener actualizados los Issues y las columnas de GitHub Projects según el avance real de cada actividad.
